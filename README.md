# DiffBeacon

WinMerge を基にした、ファイル・フォルダー比較アプリです。C# / .NET 10 / Avalonia UI への移植を進めています。**WinMerge の全機能との互換性はまだ完成していません。** 対応状況は [移行一覧](Docs/MIGRATION.md) を参照してください。

## 使い方

アプリを起動し、左と右のファイルまたはフォルダーを選んで「比較」を押します。差分を選択し「選択差分 →」または「← 選択差分」でコピーし、「左を保存」または「右を保存」で編集した側を保存します。

ウィンドウが小さく設定や操作ボタンが隠れる場合は、上部の操作欄を縦にスクロールしてください。画像ビューの操作欄もスクロールしてPNG保存などのボタンを表示できます。

入力とは別にマージ結果を作るには、比較後に「マージ開始」を押し、結果の差分を選んで「左を採用」「右を採用」などを使います。祖先ファイルも指定して比較すると、祖先の採用と4ペイン表示が使えます。「自動マージ」は祖先に対する独立変更を自動で統合します。「結果を保存」で保存先を選び、未解決の差分が残る場合は確認して保存します。入力を保持するには別の保存先を選んでください。

- テキスト：GNU diffに基づく行対応、差分・行内強調、編集、差分移動、検索、空白・大文字小文字・空行・数字・コメント・正規表現の除外、順序付き置換フィルター。処理上限時も元の全行を保持して変更区間を表示します。
- マージ結果：差分ごとに左・右（三者では祖先も）を選択し、複数の採用順序を指定。手編集と採用のUndo/Redo、未解決数、行の採用元を表示。
- フォルダー：再帰比較、内容・SHA-256・日時とサイズ、除外パス、選択項目のコピー。
- バイナリ：16進表示・編集・差分範囲コピー・別名保存。
- 画像：二者・三者表示、領域の強調と移動、差分色の不透明度（0～1）、重ね合わせ、倍率、閾値付きピクセル差分、行・列の挿入削除検出、GIF／WebP／APNGの手動フレーム選択・同期移動、TIFF／BigTIFFの主ページ比較。静止画は領域／全領域コピー、三者の自動コピー、共有Undo／Redo、原画のPNG別名保存が使えます。整列モードと未保存編集を含むHTMLも保存できます。[画像の操作と制限](Docs/IMAGE-VIEWER.md)を参照してください。
- JSON：構造の正規化。CSV / TSV：二者・三者の行合わせ、セル編集・Undo/Redo・検索。
- アーカイブ：7z／RAR／ZIP／TAR系の内容比較、暗号化・solidの読込み、プレビュー、エントリ保存・全件展開、非暗号化7z／ZIP派生／TAR系の作成・再梱包。
- XML / HTML / Web応答 / Office / TAR：標準プロバイダーで比較用テキストへ変換。外部実行ファイルは明示登録したときだけ使用。
- ファイルフィルター：旧 `.flt` の include / exclude、ファイル・ディレクトリ規則、名前・サイズ・日時の条件式。
- 比較プロジェクトの保存・読込み、WinMerge プロジェクトの読込み、unified patch、HTMLレポート。

画像の回転・反転と表示位置は対象ペインを選んで操作し、読取り専用や複数ページの表示にも使えます。「位置 ←／→／↑／↓」で1ピクセルずつ移動できます。静止画はドラッグで矩形を選び、コピー・切取り・削除・移動・貼り付け、右辺・下辺・右下角からのサイズ変更ができます。貼り付けはEnterで確定、Escapeで浮動状態を取り消します。コピーは変換・移動後の座標で行い、PNG保存は表示変換や位置を焼き込まない原画を保存します。Undo／Redoは原画を戻し、表示位置は保持します。詳しくは[画像の操作と制限](Docs/IMAGE-VIEWER.md)をご覧ください。

テキストの強調は変更ブロック内の単語を対応させ、離れた変更範囲をそれぞれ示します。詳細比較の上限に達した行は行全体を強調し、状態欄に件数を表示します。

表ビューではセルを選択して上部の編集欄を変更し、「セルを変更」で本文へ反映します。同セル内の前後検索、固定した文字選択範囲、一件・選択ペインの全置換が使えます。未反映のセル編集は先に反映・破棄してください。行・列・ペインを指定して選択し、列の多い表は「前の列」「次の列」で移動できます。詳しくは[表の操作と制限](Docs/TABLE-EDITOR.md)を参照してください。

複数の比較は「新しい比較」でタブを追加します。F7 / Shift+F7 で差分を移動できます。テキスト保存では読込み時の文字コードとBOMを保持します。バイナリと静止画像の別名保存は形式別ビューの操作を使ってください。画像はPNGへ保存し、成功した側だけのパスを更新します。多ページ編集と元形式への保存は未対応です。

アーカイブのパスワードは左右のマスク付き入力欄に指定し、「アーカイブを再比較」で読み込みます。項目を選び「左エントリを書き出す」または「右エントリを書き出す」で内容を保存できます。「左を再梱包」「右を再梱包」は選んだ側の全内容を、「アーカイブ作成」は選んだフォルダーを保存します。保存先の拡張子で7z・ZIP（jar/ear/war/xpi）・TAR・tar.gz/tgz・tar.bz2/tbz2/tbzを選びます。出力は暗号化せず、元の属性・アクセス制御・圧縮方式は保持しません。比較元への上書きはできません。

「左をすべて展開」「右をすべて展開」は、展開フォルダー名を入力して親フォルダーを選び、新しいフォルダーへ全内容を保存します。既存の展開先を上書きせず、破損などで失敗したら途中出力を公開しません。パスワードは比較プロジェクトには保存されません。

コメント構文や空白モードは比較設定で選び、置換規則は「置換フィルター…」で順番に登録します。これらは比較に使う内容だけを加工し、原文や保存内容は変えません。

「プロジェクトを保存」は、すべての比較タブの入力パス・設定・順序と選択中のタブを保存します。「プロジェクトを開く」で全タブを復元でき、複数の比較を含む旧`.WinMerge`と従来の単一JSONも読み込めます。プロジェクトは最大256比較・4 MiBです。画像はページ番号・回転／反転・表示位置・差分ブロックサイズ・閾値・倍率・重ね合わせ不透明度・差分色の不透明度・強調・表示方式・レポートの全／選択も保存・復元します。画像の未保存編集は含まれないため、原画をPNGへ保存してからプロジェクトを保存してください。編集本文、マージの採用状態・Undo/Redo履歴は含まれないため、本文は各保存ボタンで別途保存してください。

「比較の設定…」では左右の説明、読取り専用、ファイルマスク／式、表の区切り文字・引用符・引用内改行を指定します。フォルダーの再帰・比較方式・除外パスもプロジェクトへ保存します。読取り専用側への編集・コピー・入力の上書きは拒否し、内容を別の場所へ書き出すことはできます。ただし、静止画像は読取り専用側のPNG別名保存もできません。画像の共有Undo／Redoは読取り専用指定後も使えます。未対応の旧設定は保持して画面に表示します。旧プラグインや未登録の比較ツールは、プロジェクトを開いただけでは実行しません。

「比較を包装…」では、保存済みの比較タブを選び、文書・HTMLレポート・Unifiedパッチ・比較プロジェクトを1つのアーカイブへまとめます。既定では文書と比較プロジェクトを含め、レポート・パッチは必要に応じて指定します。アーカイブを新しいフォルダーへ展開して`project.json`を開くと、同梱文書から比較を再開できます。文書を含めない場合は元のファイルを参照します。保存したアーカイブをファイルとしてクリップボードへコピーする指定もできます。未保存の編集や比較後に変更したパスがある場合は、保存・再比較してから実行してください。

包装は二者・三者のローカルファイルに対応し、各256 MiB、入力と生成物の合計1 GiB、レポート・パッチ各32 MiBまでです。画像レポートには[画像の上限](Docs/IMAGE-VIEWER.md)も適用します。未保存の画像編集がある場合は包装できないため、編集した側をPNGで別名保存してから実行してください。URLはプロジェクトの参照として保持し、レポート・パッチを作るにはローカルへ保存する必要があります。フォルダー比較の包装、Webの詳細レポート、一時ZIPだけをクリップボードへ置く操作は未対応です。テキストのレポートは祖先を含む全ペインを行と行内差分で表示し、表はセル単位、JSONはキー順・数値を正規化して比較します。画像は同梱原本と同じ内容から、プロジェクトに保存した全／選択フレーム・閾値・強調設定で各入力の表示・原画と左右差分PNGをHTMLへ埋め込みます。他の形式はサイズ・SHA-256などを表示します。現在のパッチはテキスト・表の原文が対象で、他の形式だけなら空のパッチになります。

「HTMLレポート」では、現在のテキスト・表・JSON・二者／三者画像比較を1つのHTMLへ保存します。テキスト・表・JSON・静止画像の未保存の編集も反映し、入力ファイルは変更しません。プロバイダー比較では変換後のテキストを出力します。画像は表示中の確定内容と閾値を使い、既定では全フレーム、「レポートは全フレーム」を無効にすると表示中の組だけを出力します。出力はUTF-8で32 MiBまでです。比較元のパスや形式を変更した場合は先に再比較してください。生成中は「中止」で取り消せます。比較入力・フィルター・開いた／保存した比較プロジェクトへの上書きや、読取り専用に指定したフォルダー内への保存はできません。

## 対応環境

Windows x64 / ARM64、macOS Intel / Apple Silicon に対応する Native AOT 発行物を生成します。macOS の最低バージョンは14.0です。各プラットフォームの実測結果と未検証項目は [移行一覧](Docs/MIGRATION.md) を参照してください。

## 入手と起動

[GitHub Actions](https://github.com/1llum1n4t1s/DiffBeacon/actions) の成功した `.NET CI` 実行から、OS と CPU に合う `DiffBeacon-<RID>` 成果物を取得できます。

- Windows：`win-x64` または `win-arm64` の成果物を展開し、同梱ファイルを一緒に置いたまま `DiffBeacon.exe` を起動します。
- macOS：`osx-x64`（Intel）または `osx-arm64`（Apple Silicon）の成果物内の `DiffBeacon.app.tar.gz` を展開します。tar は実行権限を保持するため、展開した `DiffBeacon.app` を使ってください。署名・公証は発行工程に含まれていません。

コマンドラインでも比較できます。`DiffBeacon --help` で一覧を表示し、`DiffBeacon --compare LEFT RIGHT` でテキストを比較します。Windows では `DiffBeacon.exe`、macOS では `DiffBeacon.app/Contents/MacOS/DiffBeacon` が実行ファイルです。終了コードは0が一致・成功、1が差分・競合、2がエラーです。

テキスト比較の `--max-work N` は行対応と行内差分それぞれの処理予算を指定します。行対応を省略した場合は JSON の `lineFallback`・`lineFallbackReason` に示し、元の全行を保持して未確定部分を変更扱いにします。

画像は `DiffBeacon --image LEFT [MIDDLE] RIGHT` で全フレームを同番号で比較し、後続フレームの変更や枚数差も検出します。特定の組だけを比較するには `--left-frame N [--middle-frame N] --right-frame N` を全入力分指定します。番号は1始まり、`--threshold X` は有限の非負数（既定0）、BGRAユークリッド距離で判定します。行・列の挿入削除検出は `--insertion-deletion-mode none|vertical|horizontal`（既定 `none`）で指定します。表示位置は `--left-offset X,Y`・`--middle-offset X,Y`・`--right-offset X,Y` で非負の絶対座標を指定できます。`--report-project` でも同じ指定で保存設定を上書きしてレポートを生成でき、プロジェクト自体は変更しません。画素数などの JSON 出力と上限は [画像の操作](Docs/IMAGE-VIEWER.md) を参照してください。

表は `DiffBeacon --table LEFT RIGHT`、三者は `DiffBeacon --table LEFT RIGHT --base BASE` で比較します。`--word-level`、`--eol strict|ignore`、大文字小文字・空白などの比較設定を指定でき、元行の対応をJSONで返します。`--max-work N` で行合わせの処理予算を指定できます。上限で詳細な行合わせを省略した場合は `alignmentFallback`・`alignmentFallbackReason` に示し、元行を省略せず順序を保って対応させます。詳しくは[表の契約](Docs/TABLE-EDITOR.md#比較と原文の契約)を参照してください。

`DiffBeacon --word-diff LEFT RIGHT` は原文の変更区間を JSON で返します。`ranges` の各要素は `[左の開始位置, 左の長さ, 右の開始位置, 右の長さ]` で、位置は0始まりの UTF-16 単位です。既定では文字単位まで絞り込み、`--word-level` で単語単位にできます。`--eol strict|ignore|space`、`--separators TEXT` などの指定は `--help` で確認できます。詳細比較を省略した場合は `fallback` と `fallbackReason` に示し、両原文全体を変更区間として返します。

保存した比較プロジェクトを包装するには、`DiffBeacon --package-project project.json comparison.zip --report --patch` を使います。`--entries 1,3` で包装する比較を番号で選択でき、`--no-documents`・`--no-project` で文書・プロジェクトを除外できます。

比較プロジェクトから単体HTMLを作るには、`DiffBeacon --report-project project.json comparison.html` を使います。既定では選択中の比較、`--entry 2`では指定した番号の比較を出力します。テキスト・表・JSONの二者／三者比較と二者／三者画像比較に対応します。画像はプロジェクトに保存した全／選択フレーム・閾値・強調設定を使います。フレームと閾値は `--image` と同じオプションで明示指定すると、その値を優先します。画像設定を持たない旧プロジェクトでは全フレーム・閾値0・強調ありです。レポート生成の終了コードは、差分の有無にかかわらず成功時0です。

## 制限と困ったとき

WinMerge の旧ActiveXプラグイン、ブラウザーのDOM・JavaScript・画面比較、Explorer / Finder 拡張、インストーラー登録は未対応です。プロバイダーで変換した内容は読取り専用で、元ファイルへのテキスト保存はできません。

- 上限エラー：テキスト読込みは既定64 MiB、バイナリビューの表示・編集は各16 MiBが上限です。画像は入力各64 MiB・1600万ピクセルまでで、比較キャンバス・フレーム数・復号作業量にも上限があります。詳しくは [画像の操作](Docs/IMAGE-VIEWER.md)、変換形式の範囲と制限は [プロバイダーの説明](Src/DiffBeacon.Providers/README.md) を参照してください。
- 保存できない：読取り専用属性や書込み権限を確認してください。読込み後に入力パスを変えた場合は、比較して開き直してから保存します。
- 文字化け：BOMなしの文字コード推定は完全ではありません。読込み・保存の対応とフォールバックは [テキスト処理の説明](Src/DiffBeacon.Core/README.md#テキスト比較と保存) を参照してください。
- アーカイブを開けない：暗号化入力はアーカイブビューでパスワードを入力してください。標準プロバイダーの `archive` にはパスワードを指定できません。分割アーカイブ、リンクや危険・重複した格納名は拒否します。RAR作成と暗号化出力は未対応です。
