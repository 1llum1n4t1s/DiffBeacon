# マージ結果セッションの移植

旧`feature/4pane-merge`の`MergeDocResultPane.cpp`と`MergeResultPane.h`が根拠。共通・自動・未解決・競合・採用済み・手編集を区別し、差分ごとに左・祖先・右を順序付きで採用する。元の三者を上書きせず、結果文書を独立して保持する。

実装前に検証する失敗: 採用で隣接する独立変更を消す、最終改行なしの内容を途中へ置いて行を連結する、CRLF/BOMを結果保存で失う、二者セッションへ存在しない祖先を採用する、手編集後に古い座標で別の差分を上書きする、複数ソースの順序を逆にする、Undoで解決状態を戻さない、単なる本文内のマーカー文字を競合と数える。

CLIの`--merge-select`と通常アプリのheadless操作で元入力・結果バイト列・選択状態・画面を保存して検証する。セッション以外の未移植機能は`MIGRATION.md`に残す。

結果編集は変更した範囲だけを手編集とし、未変更の競合と行の由来を残す。生成した競合マーカーの位置を追跡し、元の本文にある同文の区切りとは区別する。差分対応が同文の生成マーカーを優先した場合も、結果が元ソースと完全一致する領域は解決済みとする。マーカーを一部だけ編集した領域は保守的に未解決として保持する。未解決の保存は明示指定が必要で、通常の保存APIはファイル作成前に拒否する。

保存は祖先（なければ左）の文字コード・BOMを保持し、元文書の保存先を変更しない。左右一致・片側不変では採用側の改行を保持する。最終改行のない採用を途中へ置く場合だけ境界改行を補い、後続の採用を空に戻すと不要な補完改行を除く。手編集と採用のUndo/Redoは本文と未解決状態を一緒に復元する。

headless E2Eは55アサーションで、未保存の結果を破棄する再開始のキャンセル、共通行と競合本文の編集、採用元表示、結合改行、本文内の区切り、保存拒否を実画面経路で確認する。入力、結果、`ui-report.json`、`merge-regressions.png`を`artifacts/verification/<RID>`へ保存する。
