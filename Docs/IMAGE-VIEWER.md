# 画像のフレーム比較

## 通常画像の操作

画像モードは二者または三者を並べ、重ね合わせ・左右のピクセル差分を表示する。三者の中央は第三の比較画像であり、テキストの祖先として解釈しない。倍率、重ね合わせの不透明度、差分閾値、強調の表示を変更できる。8×8 blockの差分を8近傍の連結領域へまとめ、前後の領域・三者の競合へ移動できる。通常色は黄、選択領域は赤。不透明な画素はRGBへ0.7で重ねて元のalphaを保持し、透明画素は原本の色とalphaを使う。左には右だけの変更、右には左だけの変更を強調しない。

各入力のフレーム番号は1から始まり、個別の番号指定・前後移動と同期移動を使える。同期移動は現在の最大番号を共通起点とし、対象ページが存在しない入力は直前の選択を保持する。初期表示は各入力の先頭。GIF、lossless WebP、APNG、TIFFの主ページを実画像で検証する。自動再生、選択位置のプロジェクト保存、色管理・EXIF方向・位置合わせは未確認または未移植。

APNGは`.png`と`.apng`から認識し、表示・比較・HTMLへ合成済みの全キャンバスを使う。既定の静止画像をアニメーションに含めない入力では、その静止画像をフレーム番号に数えない。位置・SOURCE/OVER・NONE/BACKGROUND/PREVIOUSを適用し、先頭PREVIOUSは背景の消去として扱う。SOURCEでは透明画素の色成分も保持する。遅延時間・繰返し回数を差分判定や自動再生へは使わず、複数フレームの編集・元形式保存は未対応。仕様と自作入力の範囲は[APNG fixture](../tests/Fixtures/Images/Apng/README.md)を参照する。

TIFFは`.tif`／`.tiff`のclassic TIFFとBigTIFF、両byte orderの主IFDをページとして扱う。ページごとの寸法でGUI・CLI・単体／包装HTMLへ接続し、短い入力はCLIの全ページ比較で最後のページを反復する。復号はApp内のTiffLibraryとJpegLibraryを使い、両MITライセンスを発行物へ同梱する。自作入力で非圧縮RGBA、associated alpha、PackBits、Deflate、限定LZW、palette、1bit WhiteIsZero、16bit RGB、tile、JPEG7を照合する。[TIFF fixture](../tests/Fixtures/Images/Tiff/README.md)に正確な構成と期待画素を記録する。全圧縮設定・色空間・旧JPEG6・SubIFD・方向補正・FreeImage全形式互換は検証済み扱いにしない。多ページの編集・元TIFFへの保存は未対応。

## 静止画像の編集とPNG保存

全入力が単一フレームの比較では、コピー方向を選び「選択領域をコピー」または「全領域をコピー」を使う。二者は左右の2方向、三者は左・中央・右の6方向に対応する。選択領域は赤く表示され、領域の矩形内でも別の領域や穴に属する画素はコピーしない。操作後は編集済み原画で再比較して領域と強調を更新する。

三者の「競合以外を自動コピー」は隣のペイン選択欄でコピー先を指定する。中央へは左だけ・右だけの変更を各側からコピーし、左または右へは中央だけの変更をコピーする。競合領域は保持する。全領域コピーと自動コピーはそれぞれUndo一件で、全ペイン共有の「元に戻す」「やり直す」を使える。読取り専用の側へコピー・自動コピー・PNG保存はできない。読取り専用へ切り替えた後も、既存の履歴のUndo／Redoは使える。

保存する側を選び「PNGで別名保存…」で原画を32bit PNGへ保存する。領域の強調色や重ね合わせ表示は保存せず、透明RGBとalphaを保持する。成功すると保存した側だけの入力パスと保存点が更新され、他の側のパス・未保存編集は保持される。元の入力や現在の比較入力へ上書きせず、別のPNGを指定する。全タブの入力・フィルター・比較プロジェクト、読取り専用出力、リンク経由の保存先も保護する。

コピー・再比較・描画が完了してから仮状態を採用するため、失敗・取消では直前の原画・履歴・表示を保持する。PNG保存中は編集・ページ変更・再比較・編集破棄を待ち、「中止」で保存を取り消せる。保存先の置換前に失敗・取消した場合は既存出力と保存点・パスを保持する。履歴は128件・256 MiB、コピー走査と再比較の累積作業は256Mピクセルまで。

多ページ画像は閲覧・比較専用で、領域編集とPNG保存は使えない。元形式・palette／BPP・アニメーションcontainerの保存は未対応。拡張canvasはzero-filled BGRAを使い、FreeImageの完全互換は未実測。検証結果と通常デスクトップを含む実測範囲は[移行一覧](MIGRATION.md)を参照する。小さいウィンドウでは共通設定欄と画像操作欄をスクロールして操作する。

## CLIのフレーム比較

`DiffBeacon --image LEFT [MIDDLE] RIGHT` は全フレームを同番号で比較する。短い入力は最後のページを繰り返す。先頭が同じでも後続の変更とページ数の差を検出する。特定の組だけなら `--left-frame N [--middle-frame N] --right-frame N` を全入力分指定する。異なる番号の組も比較できる。

`--threshold X` は有限の非負数（小数点は .）、既定0。共通範囲ではBGRAユークリッド距離が閾値を超える画素を差分とする。色・透明度はBGRA8888 Unpremul。領域候補は三者の左対中央または右対中央の差分、分類は左だけ1・中央だけ2・右だけ3・競合4。only分類が同一領域内で混在しても競合となる。二者の原本分類は全領域4。原本の三者共通gridに対する寸法差とunsigned高さ減算の挙動も保持する。

終了コードは一致0、差分または全ページ時の枚数差1、入力・上限エラー2。成功JSONは `different`、各入力のフレーム数、モードと閾値、`frames` を返す。各要素は元番号・寸法・行詰め原画BGRAのSHA-256、左右だけの差分画素数・比較画素数、領域数・分類・block矩形（右・下は排他的）、原本強調後の各pane SHAを持つ。三者の差分有無は全領域で判定するため、左右画素差が0でも中央だけの変更を検出する。失敗時は成功JSONを出さず、元入力を変更しない。画像をテキスト保存しない。

## HTMLと包装

「HTMLレポート」は全入力の強調画面と原画、左右のピクセル差分をPNGで埋め込んだ自己完結HTMLを作る。「レポートは全フレーム」は既定有効。無効なら表示中の組だけを出す。GUIは確定した画像・閾値・選択領域・強調表示設定を使い、静止画の未保存編集も反映する。元ファイルの事後変更を混ぜず、選択を動かさない。画像の操作・PNG保存中は完了してから生成する。

CLIは `--report-project INPUT_PROJECT OUTPUT_HTML` で二者・三者の全フレームを出す。画像にだけ全入力分のフレーム指定と `--threshold X` を指定できる。包装の「レポート」も同じ生成器を呼び、同梱原本の確定内容から全フレーム・閾値0で作る。GUIの包装は未保存の画像編集が残っていれば拒否する。編集した側をそれぞれPNGへ保存してから包装する。PNGはHTMLに含み、外部ファイル・URLを必要としない。

HTMLはbase64と本文を含むUTF-8で32 MiBまで。包装はさらに入力と生成物の合計1 GiBまで。復号・生成・取消の失敗では既存出力を保持する。全タブの原本・中央入力・フィルター・入力プロジェクトへの上書き、リンク経由・読取り専用フォルダー内への出力を拒否する。

## 上限と復号

各入力64 MiB、各画像と選択した組の共通キャンバス1600万画素、各入力1024フレームまで。復号作業の上限は全入力の合計256M。GIF／WebP／APNGはフレームの1始まり番号×画像の画素数を保守的な作業量として数える。TIFFは各ページのstrip／tileの端のpaddingを含めた展開画素数を使う。全フレームでは短い入力の反復復号も含めた総和、選択比較では指定組の和を確認してから復号する。描画作業は各組の共通canvas×（入力数+左右mask1）の総和で、別途256Mまでとする。上限時は入力を保持して拒否する。

TIFFは復号前に全主IFDの範囲・循環・型・タグ順と重複、strip／tile配列・寸法・参照範囲を検査する。共有タグ65536件・metadata64 MiB、segment65536件／ページ、復号scratch128 MiBを上限とし、巨大な宣言からの確保を拒否する。旧JPEGのtable数・参照範囲、JPEGの宣言寸法・scanと終了markerも検査する。この構造検査はJPEGの全entropyの正当性やTIFFの全仕様適合を保証するものではない。

復号が不完全と返された入力を拒否する。APNGは制御チャンクを認識した後に静止PNGへ退避せず、全チャンクのCRC・順序・連続sequence・矩形・枚数・IENDを検査する。各選択フレームまでのPNGデータを完全復号してから採用する。その他の形式ではデコーダーが完全な画素を返せる場合、GIF末尾や静止PNGのIENDなどが欠けても成功する場合があり、コンテナー全体の構造・CRCを独自に検証する契約ではない。読込み、復号の前後、画素・領域・描画の走査、ハッシュ、画面交換で取消を確認する。ネイティブの一回の復号中は中断せず、返却後に確認する。古い完了は破棄し、置換・終了でbitmapとCTSを解放する。

## 原本照合の入口

開発用 `DiffBeacon --image-regions LEFT [MIDDLE] RIGHT` は通常操作と同じWinIMerge v1.0.54の領域処理を呼び、全pair grid・領域ID・矩形をJSONで出す。既定は先頭、block size=8、threshold=0。`--block-size N` は1..256。全grid出力は262,144blockまで。フレームと閾値の指定は通常CLIと同じ。`--highlight-alpha X`（0..1）または `--selected-region N`（1始まり、0は未選択）の指定時だけ強調後の各paneの寸法・SHAを追加する。位置合わせ・回転・挿入削除検出・画像マージ・原本overlay/wipeはこの照合に含めない。

原本の無改変関数・SHA・ライセンス・採取範囲は[領域fixture](../tests/Fixtures/ImageRegions/README.md)と[強調fixture](../tests/Fixtures/ImageHighlight/README.md)を参照する。復号用の独立した全RGBA/BGRA期待値は[画像fixture](../tests/Fixtures/Images/README.md)、実測範囲は[移行一覧](MIGRATION.md)へ記載する。

## 静止画像コピー核の診断

開発用 `DiffBeacon --image-copy LEFT [MIDDLE] RIGHT --script SCRIPT_JSON [--hashes-only]` は単一フレームの二／三者画像を復号し、GUIと同じ原画の領域コピーと全pane共有のUndo／Redoを実行する。offset・回転・挿入削除は使わない。拡張canvasの初期値はzero-filled BGRAで、FreeImageの新規画素・paste処理の完全互換は未確認。[コピーfixture](../tests/Fixtures/ImageCopy/README.md)の無改変原本143ケース・935状態を期待値とする。

scriptは `blockSize`（1..256、既定8）、`threshold`（有限の非負数、既定0）、`readOnly`（入力数と同じbool配列、既定全false）、`actions` を持つJSON object。操作のpane・領域indexは0始まり。未知・重複property、未知kind、必要値の欠落を拒否する。

| kind | 必須値 | 処理 |
| --- | --- | --- |
| `copy` | `src`, `dst`, `index` | 選択領域のIDに属するblockの全原画BGRAをコピー |
| `all` | `src`, `dst` | 全領域をコピーし、Undo一件として再比較 |
| `auto` | `dst` | 中央には左右only、外側には中央onlyをコピー。競合は保持 |
| `undo` / `redo` | なし | 全pane共有履歴を移動して再比較 |
| `save` | `dst` | 診断用のsavepoint mark。ファイルを保存しない |
| `set-savepoint` | `dst`, `index` | 診断用のsavepoint復元 |
| `export` | `dst`, `path` | 原画を32bit PNGへ別名保存し、成功状態へsavepointを進める |

例えば `{"actions":[{"kind":"all","src":0,"dst":1},{"kind":"export","dst":1,"path":"result.png"}]}` は左の全差分を右へコピーしてPNGへ保存する。領域の矩形内に別の領域があれば触らない。コピー元は強調画面ではない。原本に合わせ、差分0の全コピーや採用0のautoも一件の履歴となりdirtyにする。コピー／再比較は仮状態で完了させてから確定し、Undo後の新編集は旧Redoを破棄する。

PNGはUnpremulの原画から生成し、透明RGB・alphaを保持する。入力全画像と操作scriptへの上書き、読取り専用pane・既存出力、リンク経由の入出力を拒否する。同じディレクトリの一時ファイルから原子的に置換し、既存属性とUnix modeを保持する。元形式・BPP／palette・アニメーション／多ページcontainerの保存ではない。

scriptは1 MiB・64操作、履歴は128件・256 MiB、コピーblock走査と再比較の累積作業は256Mピクセルまで。診断の全gridは262,144block、JSONは32 MiBまでで、原画base64の増幅も変換前に確認する。`--hashes-only` は原画base64だけ省略する。全操作と全stateのシミュレーション・JSON出力検査を完了してからexportを保存するため、その前の構文・予算エラーでは既存出力を保持する。複数exportは各ファイルを順次保存し、途中のOS保存失敗時に先行ファイルまで巻き戻す契約ではない。成功は差分の有無によらず終了コード0、失敗2。JSONは初期状態と各操作後の原画・領域・履歴／dirty／savepointを返す。
