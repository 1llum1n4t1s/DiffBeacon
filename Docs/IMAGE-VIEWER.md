# 画像のフレーム比較

## 原本の差分領域処理の照合

開発用 `DiffBeacon --image-regions LEFT [MIDDLE] RIGHT` はWinIMerge v1.0.54のブロック差分・8近傍連結領域・三者分類をC#へ移植した処理を呼ぶ。中央は第三比較画像であり、祖先として解釈しない。通常のGUI・`--image`・HTMLへの接続前に原本との一致を確認する入口であり、以下の通常画像操作を置換したものではない。

既定は各入力の先頭、block size=8、threshold=0。`--block-size N` は1..256、`--threshold X` は有限の非負数（小数点は .）。BGRAユークリッド距離が閾値を超えた画素を含むblockを差分とする。`--left-frame N [--middle-frame N] --right-frame N` は全入力分を指定する。既存の入力・画素・フレーム数・共通キャンバス・合計復号量の上限を守り、開発用JSONの全grid出力は262,144blockまでとする。

JSONは01・21・02の0/-1 grid、連結領域ID、block座標の矩形（右・下は排他的）、領域数、分類を出す。三者候補は01∨21、領域の分類はLeftOnly=1、MiddleOnly=2、RightOnly=3、Conflict=4。同じ領域内のonly分類が混在しても競合とする。二者は原本どおり全領域が4となる。終了コードは領域なし0、あり1、エラー2。原本の三者共通gridに対する寸法差挙動も保持する。[固定fixtureと採取範囲](../tests/Fixtures/ImageRegions/README.md)を参照する。位置合わせ・回転・挿入削除検出・表示加工・画像マージはこの照合に含めない。

## 通常画像の操作

画像モードで左右・重ね合わせ・ピクセル差分を表示する。倍率、右の不透明度、差分閾値を変更できる。左右のフレーム番号は1から始まり、個別の前後移動と番号指定、同期の前後移動を使える。同期移動は現在の最大番号を共通起点とし、ページ数が少ない側は末尾に留まる。初期表示は各側の先頭。GIFとlossless WebPの複数フレームを実画像で検証している。自動再生、選択位置のプロジェクト保存、TIFF/APNGの全ページ、色管理・EXIF方向・位置合わせ・画像マージは未確認または未移植。

`DiffBeacon --image LEFT RIGHT` は全フレームを同番号で比較する。先頭が同じでも後続の変更とページ数の差を検出する。片側にしかないページは、その側の全画素が差分となる。

特定の組だけを比較する場合は `--left-frame N --right-frame N` を両方指定する。左右の番号が異なる比較もできる。`--threshold N` は0～255、既定0。共通範囲ではBGRA各成分の最大差が閾値を超えた画素を差分とし、画像サイズ外は閾値にかかわらず差分とする。色・透明度はUnpremulで比較する。終了コードは一致0、差分1、入力・上限エラー2。

成功JSONには `different`、左右のフレーム数、比較モードと閾値、`frames` 配列を返す。各要素は左右の元フレーム番号・寸法・行詰めBGRA8888 Unpremulの画素SHA-256、差分画素数と比較画素数を持つ。欠落側の番号・寸法・SHAはnull。失敗時は成功JSONを出力しない。元入力を変更せず、画像をテキスト保存しない。

画像比較から「HTMLレポート」を保存すると、左右の画素とピクセル差分をPNGで埋め込んだ自己完結HTMLを作る。「レポートは全フレーム」は既定で有効。同番号の全フレームと枚数差を出し、無効にすると表示中の左右の組だけを出す。閾値は表示中の確定値を使い、選択位置を動かさない。GUIでは比較時に確定した画像を使い、読込み後に元ファイルの内容が変わってもレポートに混ぜない。フレーム変更中は完了してから保存する。

CLIは `--report-project INPUT_PROJECT OUTPUT_HTML` で画像比較の全フレームを出す。画像にだけ `--left-frame N --right-frame N` と `--threshold N` を指定できる。包装の「レポート」も同じ全フレーム生成器を使い、同梱原本の確定内容から生成する。PNGはHTML内に含め、画像の隣接ディレクトリや外部URLを必要としない。三者画像の詳細HTMLは明示的に拒否する。

HTMLはbase64の増幅と本文を含むUTF-8で32 MiBまで。包装ではさらに入力と生成物の合計1 GiBの制限を受ける。復号・生成・取消の失敗では既存出力を保持する。全タブの原本・祖先・フィルター・入力プロジェクトへの上書き、リンク経由・読取り専用フォルダー内への出力を拒否する。

各入力は64 MiB、各画像と比較キャンバスは1600万画素、各入力は1024フレームまで。復号作業の上限は左右合計256Mで、各フレームの1始まり番号×その画像の画素数を保守的な作業量として数える。全フレーム比較ではその総和、選択比較では選択した組の和を確認してから復号する。上限時は入力を保持して拒否する。

復号が不完全と返された入力を拒否する。デコーダーが完全な画素を返せる場合、GIFの末尾やPNGのIENDなどが欠けていても成功することがある。コンテナー全体の構造・CRCを独自に検証する契約ではない。キャンセルは読込み、復号の前後、画素走査、ハッシュ作成、画面交換で確認する。ネイティブの一回の復号呼出し中は中断せず、返却後に確認する。
