# Failure matrix (written before implementation)
Scope: fixed native StrCount/StrFind function bodies and their raw helper bodies only. Managed parser, optimization, loader, scanner, public .flt acceptance are excluded.
- Raw source differs in bytes, size, SHA-256 or Git blob SHA-1: refuse compilation and reader verification. Copy original blobs unchanged; preserve all provenance and licenses.
- Function name/arity: registration specifies lowercase names; constructor lowercases names; StrCount strict 2 and Find 2..3. Body-only wrong arity and null args return None without evaluating arguments. Constructor/parser compile errors are source evidence, not native execution evidence.
- Evaluation order: valid arity evaluates source then needle then optional occurrence. Inject tagged exceptions separately at each argument and assert trace stops there. Invalid/empty needle still evaluates occurrence. Wrong occurrence type returns None after third argument evaluation.
- Needle: None, bool, Int64, double, arrays and empty string return scalar None without coercion. Byte string including NUL is accepted; longer needle, empty source and no match distinguish Count Int64 zero from Find None.
- Source: None stays None; bool/Int64/double stringify with original ToStringValue. Direct array maps only one level, preserving None; nested array stringifies as one scalar. Empty array gives empty array; invalid needle returns scalar None even for array source.
- Occurrence: omitted equals native Int64 zero; Int64 0/1/2, negative, min/max, overlarge/no-match; double 0.0/1.0, bool, string, None, array are rejected rather than converted.
- Search: overlapping aaa/aa and aaaaa/aa; ordinal sensitive and ASCII-insensitive; Unicode accented/fullwidth/expanding case pairs do not fold. UTF-8 byte positions after multibyte prefixes; embedded NUL and high bytes.
- Oracle integrity: generate typed literal arguments, compile exact unchanged extracted bodies, record compiler and process PID/birth/exit/stdout/stderr hashes and EOF; two disjoint output directories and two real compilations/executions. Reader checks receipts, executable/source/include hashes and identical run outputs.
- Golden integrity: unique IDs and nonempty case set, exact typed values/status/error/left-to-right argument trace; compare every output against an independent byte-based model and fixed golden, not managed code.
- Boundaries: unsupported Poco date/regex/file-content are fail-fast bindings and unconstructed. No production dependencies or builds. No parser, optimizer, folder variable/scanner or .flt end-to-end coverage is inferred.
