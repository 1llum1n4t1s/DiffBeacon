# Saved Archive reload failure contract

This contract is derived from the pre-implementation input348 failure specification; historical flat-route criteria remain independent evidence.

- Flat or nested root ZIP → inner.zip → deep.zip → docs/leaf.txt selection must not silently replace one side or omit the actual entry/dialog/browser/Compare/new-tab adoption controls.
- All three working saves must preserve literal encoding, BOM and mixed EOL. Original ZIP/container/leaf bytes, all entries/CRC/SHA and readonly leaves must remain unchanged; inherited=false permits working edits without making the original writable.
- Project-save, no-patch packaging, project-open, ordinary Archive package-open, actual extract-all and extracted project-open must all complete through original button Tasks. A direct API or package-open alone cannot substitute for the extraction/reload sequence.
- All saved asset bytes, relative references, restored three editable bodies, metadata and clean savepoints must match literals. Missing/extra package or extracted entries, missing observations/controls/Tasks and missing case/output/PNG fail independently.
- References reject portable absolute/UNC/drive syntax, empty/NUL and any parent segment. Runtime file resolution must remain inside the known run and reject symlinks/escaping targets.
- The separate reader must validate exact source/input pins, size/SHA, complete ZIP entry CRC and independently decode every PNG scanline. Fixture-only results, process timeout or partial stdout/stderr are not product success; preserve actual PID/birth/exit and complete streams.

Use fresh C-drive output; preserve E-drive evidence read-only. Regeneration occurs only in a new directory. Native OS pointer/pickers, encrypted nested cases, macOS and AOT are separate; a 120-second limit is not completion evidence. Historical 6,023-check route receipts do not qualify strengthened source-pin, permission, encoding or path criteria.

- Container-parent regression (EntryChain one and two): a legitimate Archive comparison with null LeafEntry must complete its real Compare Task, then open the public independent-input button/dialog Task. Each initial browser must retain its container route, select no leaf and reject an actual Compare submission (wait its original Task; retain the dialog and parent tab) until real listing Load and explicit leaf selection. Initial container listing must be revalidated without a picker replacing its route. Repeated same-kind picker selection is measured independently at the root in both existing flat/nested cases (and the fresh middle side of each container case). The one-level case must open deep.zip through its original Open Task. Both cases must adopt a new independent Text tab through the original Compare/submission/open Tasks with exact literal bodies, readonly original leaves, unchanged full ZIP entries/CRC/BOM/EOL and no implicit initial leaf. Reader must fail closed on absent or extra container cases, routes, controls, Tasks, permission facts or PNGs.

- Initial RootPath text must not deliver a delayed change that erases the inherited container chain. Record the first original read request and complete literal listing for both depths. Repeating the same-root picker preserves that chain; picking a different root clears chain, leaf, verified state and extra password fields, revalidates the new root, and must not implicitly select a leaf. Restore the original root and navigate explicitly before adoption. Keep the failed slash/picker diagnosis as a retracted hypothesis; the picker-free original request/listing is the cause evidence.
