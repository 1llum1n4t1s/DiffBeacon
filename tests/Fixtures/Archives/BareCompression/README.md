# Bare BZip2 / Z fixture

Synthetic data, generator, and independent reader are dedicated to CC0-1.0.
The ZIP stores 22 small fixed inputs with deterministic timestamps; expected.json records full decoded hex, sizes and SHA-256. Mixed File/Tar/File and File/Auto/File routes prove that selections do not implicitly propagate between addressed layers.
Z generation and independent decoding use the official ncompress 5.1 reference built by `build/Build-ZReference.ps1` on Windows (MSVC, `ncompress.exe`) or macOS (clang, `ncompress`). Executable SHA varies by compiler and host; qualification requires the adjacent `build-proof.json`, successful compiler exit, exact declared decoder/source paths, and actual decoder/compiler bytes matching their recorded SHA. No decoder or compiler is executed during qualification, and no compiler is searched for automatically.

The fixed repository originals in `tests/Fixtures/Archives/TarZ/reference-source` are read and checked before any decoder execution: `compress.c` SHA-256 `29C5A78005921A7881D8C83EA711E826C8C87F354B4A2F47F8C474117F6646D8`, `patchlevel.h` `458F2AF3AA2862B80E52D45F277FDA6D105A225DD0629ECA9153DD3B060B47A3`, and `UNLICENSE` `7E12E5DF4BAE12CB21581BA157CED20E1986A0508DD10D0E8A4AB9A4CF94E85C`. Manifest declarations alone cannot qualify source bytes. Missing/malformed/duplicate-property proof, nonzero compiler exit, changed bytes or mismatched paths are rejected. Decoder, proof, source and every ancestor reject links/reparse points. Only the recorded compiler path may follow a system alias, to accommodate macOS; its actual bytes must still match the proof.

Regenerate outside the repository: `python -B generate.py --output <external task directory> --z-reference <qualified ncompress>`; qualification completes before creating or writing output. Existing fixed `inputs.zip` and `expected.json` remain immutable; this change does not regenerate them.
Verify all ZIP entries/CRC, all BZip2 members and bytes, and official Z bytes: `python -B verify.py --root <fixture directory> --z-reference <qualified ncompress>`.
Standalone Python defaults to the sibling repository `TarZ/reference-source` directory. When scripts/fixtures are copied outside the repository, add `--reference-source <absolute repository tests/Fixtures/Archives/TarZ/reference-source>`; it must exactly match the build proof source location and contain the fixed original bytes. The E2E runner supplies this repository path explicitly. Qualification alone: `python -B generate.py --z-reference <qualified ncompress> --reference-source <repository source directory> --validate-reference-only`.
After public CLI E2E: add `--run <bare-compression run directory>` to independently compare every successful File export byte for byte.

BZip2 checks member EOF/footer/CRC including later corrupt and empty members. Z has no checksum, declared decoded size or explicit EOF; semantic corruption and nonzero padding cannot be classified as universally invalid.
Fixed bytes require `inputs.zip -text -eol` and `expected.json -text -eol`; all Python scripts also require `*.py -text -eol` so Windows checkout preserves their qualified SHA-256. Git must report both attributes as unset for these paths.

To select fixed fixtures outside the repository, use the E2E runner value option `--bare-compression-fixtures <absolute fixture directory>`. Example: `dotnet <E2E runner.dll> --bare-compression-only --bare-compression-fixtures <external fixture directory> --output <external owned run> --app <DiffBeacon.dll> --z-reference <qualified ncompress>`. Omitting the override uses `tests/Fixtures/Archives/BareCompression`.

Both E2E fixture paths require complete fixed SHA-256 for inputs.zip/expected.json and for the executed verify.py plus its imported generate.py. The allowlist includes the official verify-ui.py and UI-CONTRACT.md; unknown files, directories and links are rejected. Input directory, scripts and reference reject links through all ancestors; fixture root cannot overlap run output. Original files are read only and every original SHA is compared again after the run. Before any run output is created, a fixed-script qualification process has a 60-second deadline and must exit successfully with both output streams at EOF. The run writes `fixture-input-proof.json` with absolute fixture/output/script/reference locations, original SHA values and qualification PID/start/exit/EOF and source/build-proof/decoder SHA evidence. Python runs with `-B`, preventing bytecode output beside original scripts. Local `.gitattributes` protects all Python scripts, `inputs.zip`, and `expected.json` with `-text -eol`.

For GUI validation, run `dotnet <DiffBeacon.dll> --self-test <external run> --bare-compression-only`, then `python -B verify-ui.py --run <external run>/fixtures/<generated run>/bare-compression`. The reader checks the generated proof, complete original/decoded bytes, working saves, workspace assets and PNG/layout evidence. See [GUI validation contract](UI-CONTRACT.md) for required cases, verified scope and remaining qualification.
